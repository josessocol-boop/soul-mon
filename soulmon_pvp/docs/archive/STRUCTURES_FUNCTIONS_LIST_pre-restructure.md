## Core Structures

### Classes

#### 1. Fighter (`fighter.gd`)
**Base class for all fighters**
- **What it does:** 
  - Implements core combat mechanics (movement, attacks, defense)
  - Manages hitboxes, hurtboxes, and collision detection
  - Handles hitstun, teching, wavedashing, and movement states
  - Manages visual effects, sprites, and status indicators
  - Coordinates with subsystems (input, stats, state machine, synergy, support)
- **Connected to:** 
  - InputHandler (creates one), StatsComponent (creates one), StateMachine (creates one)
  - SynergySystem (creates one), SupportSystem (creates one)
  - Area2D nodes (hitbox, hurtbox) and Sprite2D nodes (visual effects)
  - All fighter archetypes inherit from this class

#### 2. Fighter Archetypes (fighter_*.gd)
**Specialized fighter classes**
- **Examples:** fighter_marshadow.gd, fighter_gholdengo.gd, fighter_blaziken.gd, etc.
- **What they do:**
  - Override _apply_archetype() to set fighter-specific stats (HP, speed, jump, etc.)
  - Override _define_moves() to define unique move sets
  - Every roster fighter also defines `basic_down`, `special1_down` and `special2_down` inside `_define_moves()` as `m["<key>_down"] = variant(m.<key>, {...})` (see "Down move guide" at the end of this file)
  - Set fighter-specific visuals (sprite sheet, effect textures, colors)
  - Inherit all core combat functionality from base Fighter class
- **Connected to:**
  - Base Fighter class (inheritance)
  - Specific asset files (sprite sheets, effect textures)
  - Unique move definitions and stats

#### 3. InputHandler (`input_handler.gd`)
**Manages input buffering and action detection**
- **What it does:**
  - Tracks button presses with frame-based buffering for forgiving inputs
  - Separates local input from potential network input (remote mode)
  - Implements `hold_all` (no buffer decays during hitstop, presses still recorded), `fresh()` (press is at most N frames old, used by tech) and `down_held` / `down_at` / `wants_down()` (remembers whether Down was held when each button was pressed)
  - Implements `hold_buffers` (combat presses are held alive while a long move plays, until its last `BUFFER_TAIL` frames) so mashed follow-ups fire the moment the move ends
  - Registers keys by delegating to `Keybinds.register()` (all bindings live in `keybinds.gd`)
  - Registers all gameplay actions in InputMap
  - Provides want() and consume() methods for checking and using buffered inputs
  - Records each press the moment it arrives (`_input()` -> `_pending`), so a fast tap between two physics ticks is not lost; a Down press or tap sets `down_latch` (`DOWN_LATCH_FRAMES` = 8)
- **Connected to:**
  - Each Fighter instance (1:1 composition)
  - InputMap (registers gameplay actions)
  - Fighter's _try_actions() and poll() methods

#### 4. StatsComponent (`stats_component.gd`)
**Manages fighter statistics and status effects**
- **What it does:**
  - Tracks HP, max HP, stamina, max stamina
  - Implements stamina regeneration and exhaustion mechanics
  - Manages status effects (burn, poison, slow) as frame counters
  - Provides elemental type system with weakness/resistance/immunity calculations
  - Handles damage over time effects (burn, poison)
  - Provides speed modification based on slow status
- **Connected to:**
  - Each Fighter instance (1:1 composition)
  - Fighter's receive_hit(), take_dot(), and _check_death() methods
  - Status effect application methods (apply_burn, apply_poison, apply_slow)
  - Elemental type lookup (type_multiplier static method)

#### 5. StateMachine (`state_machine.gd`)
**Handles state transitions for fighters**
- **What it does:**
  - Calls fighter.state_<state_name>(delta) each physics frame
  - Manages enter_<state>() and exit_<state>() hooks when changing states
  - Tracks frames spent in current state
  - Untyped fighter reference to avoid circular dependencies
- **Connected to:**
  - Each Fighter instance (1:1 composition)
  - Fighter's state methods (state_idle, state_run, state_attack, etc.)
  - Fighter's enter/exit state hooks

#### 6. SynergySystem (`synergy_system.gd`)
**Manages burst gauge, burst mode, and ultimate abilities**
- **What it does:**
  - Tracks Synergy Burst gauge (0-1000) that fills through combat actions
  - Manages Burst State (READY, ACTIVE, COOLDOWN, ULTIMATE_USED)
  - Implements Burst Mode activation (temporary powered state)
  - Gates Ultimate ability behind full burst gauge during Burst Mode
  - Emits signals for gauge changes, burst state changes, and ultimate usage
  - Allows archetype-specific fill multipliers
- **Connected to:**
  - Each Fighter instance (1:1 composition)
  - Fighter's burst-related variables and traits
  - Fighter's hit connections (on_hit_connect, on_damage_dealt, on_damage_taken)
  - Fighter's burst callbacks (_on_burst_activated, etc.)
  - Fighter's ultimate readiness and usage methods

#### 7. SupportSystem (`support_system.gd`)
**Manages support Pokémon calls**
- **What it does:**
  - Tracks up to 3 support Pokémon slots with individual cooldowns
  - Manages active support effects (duration-based buffs)
  - Provides static definitions for support Pokémon (Pikachu, Eevee, Chansey, etc.)
  - Handles support effect application (instant and duration effects)
  - Tracks damage buffs from support effects
  - Emits signals for support calls, readiness, and cooldowns
- **Connected to:**
  - Each Fighter instance (1:1 composition)
  - Fighter's support-related variables and callbacks
  - Support definitions (static get_support_definition)
  - ArenaManager (for spawning support effects)

#### 8. ArenaManager (`arena_manager.gd`)
**Central game manager**
- **What it does:**
  - Builds and owns the game arena, fighters, HUD, and UI flow
  - Manages fighter selection and match initialization
  - Handles game modes (PvP, PvCPU, CPUvCPU)
  - Manages camera, sound effects, and visual juicing
  - Processes fighter signals (hits, events, deaths) for game reactions
  - Handles restarts and victory conditions
  - Loads and manages the fighter roster
- **Connected to:**
  - Two Fighter instances (p1, p2) - 1:2 composition
  - HUD (displays fighter information)
  - CharacterSelect (character selection screen)
  - AIController (for CPU fighters)
  - ArenaCamera and Sfx (visual and audio systems)
  - Fighter signals (died, got_hit, event)
  - ROSTER constant (list of available fighters)

#### 9. HUD (`hud.gd`)
**Displays fighter information and controls hint**
- **What it does:**
  - Shows two fighter HUD blocks (P1 top-left, P2 top-right)
  - Displays legible controls hint in translucent panel at bottom
  - Shows round winner banners
  - Binds to two Fighter instances to display their stats
  - Updates each frame from bound fighters' stats
- **Connected to:**
  - Two Fighter instances (via bind method)
  - FighterHUD instances (P1 and P2 blocks)
  - Banner label (round announcements)
  - Help panel (controls hint)
  - ArenaManager (added as child and updated each frame)

#### 10. FighterHUD (`fighter_hud.tscn` + `fighter_hud.gd`)
**Displays individual fighter stats**
- **What it does:**
  - Shows HP bar, stamina bar, and status effect indicators
  - Displays skill slots for special moves
  - Shows fighter name and color coding
  - Updates from fighter's stats each frame
- **Connected to:**
  - HUD (instanced as P1 and P2 blocks)
  - Individual Fighter stats (HP, stamina, etc.)
  - Status effect icons (burn, slow, poison)
  - Skill slots (for special move visualization)

#### 11. Projectile (`projectile.gd` + `projectile.tscn`)
**Handles projectile behavior**
- **What it does:**
  - Moves in a straight line with configurable speed
  - Applies hit effects when colliding with fighters
  - Supports vertical velocity per shot (for spread shots)
  - **Down-move toolkit:** `proj_gravity` (lobs / arcs), `proj_bounce` (skips off the floor: only when moving down and its centre is inside the floor; each skip sets `vy = -max(|vy| x 0.8, 320)`), `proj_pierce` + `proj_hit_gap` (passes through fighters, re-hits the same fighter at most every `proj_hit_gap` seconds), `root` (sets the target's `rooted_time` on a connected hit); the shooter can fire it either way (`setup(shooter, dir, move, vy)` - melee `wave` moves send one each way)
  - Checks enemy hurtboxes first (so a point-blank shot at someone against a wall still hits), then frees itself only when its centre is inside a `StaticBody2D` (after `WORLD_GRACE_FRAMES` = 2 frames); `receive_hit()` returning false (i-frames, counter, projectile block) lets it fly on
  - Emits shot event when spawned
- **Connected to:**
  - Fighter's _spawn_projectile() method
  - ArenaManager (added as child to combat_root)
  - Fighter's move definitions (projectile kind moves)
  - SupportSystem (for support projectile effects)

#### 12. Trap (`trap.gd` (no scene: `Fighter._spawn_trap()` creates it with `load("res://trap.gd").new()`))
**Handles trap behavior**
- **What it does:**
  - Spawns at a distance from the fighter in the facing direction
  - Waits for fighters to touch it before activating
  - Applies hit effects when triggered
  - Can be configured as persistent or one-time use
  - **Down-move toolkit:** `trap_delay` (seconds before it arms; it blinks and shows only a flat marker while arming), `trap_size` (hit area; the sprite is stretched over it, e.g. the wide Whirlpool and tall Gilded Geyser), `trap_step` (extra distance per trap when `spawn_count` > 1, used by Poison Pit and Gilded Geyser), `root` (target cannot move/jump for that long), `fx_tint` (tints the trap sprite)
  - Emits trap_set event when spawned
- **Connected to:**
  - Fighter's _spawn_trap() method
  - ArenaManager (added as child to combat_root)
  - Fighter's move definitions (trap kind moves)
  - SupportSystem (for support trap effects)

#### 13. AI System (`AIController.gd`, `AIBehavior.gd`, `AIProfile.gd`)
**Provides computer-controlled fighter behavior**
- **What it does:**
  - Implements behavior tree-based AI for fighters
  - Supports multiple difficulty levels (easy, medium, hard)
  - Can target specific fighters and adapt behavior
  - Uses AI profiles to define fighter-specific tendencies
  - Implements behaviors like aggression, spacing, and move selection
- **Connected to:**
  - ArenaManager (_attach_ai method)
  - Fighter instances (added as child when CPU-controlled)
  - Target fighter reference (set via set_target)
  - AI behavior trees and profiles

#### 14. ScreenShake (`screen_shake.gd`) - **Phase 4 - LEGACY: not instantiated anywhere; replaced by ArenaCamera (see Class 26)**
**Camera shake effect system**
- **What it does:**
  - Extends Camera2D to provide screenspace shake
  - `shake(strength: float, frames: int)` - triggers shake with linear decay over duration
  - Strength is compared against current shake; only stronger shakes override
  - `offset` is updated each physics frame with random vector scaled by remaining time fraction
- **Connected to:**
  - ArenaManager (created in _build_juice, set as current camera)
  - ArenaManager._on_got_hit() calls camera.shake() with amplitude based on damage
  - ArenaManager._on_fighter_event() shakes on ultimate

#### 15. HitVfx (`hit_vfx.gd`) - **Phase 4**
**Elemental hit burst visual effects**
- **What it does:**
  - One-shot Node2D that spawns impact ring + sparks + element-colored particle emitters
  - Static `spawn(parent: Node, info: Dictionary)` factory method
  - 12 element-specific styles (Normal, Fire, Water, Grass, Ice, Steel, Ghost, Fighting, Fairy, Bug, Dark, Poison)
  - Each style defines: colors, particle count, velocity range, gravity, size, lifetime, spread
  - Super-effective hits (mult > 1.0) add gold star burst overlay
  - KO hits (info.ko) and heavy hits boost particle counts and ring size
  - Auto-cleans up after 1.2s via timer
  - Draws expanding ring in _draw() for 0.18s
- **Connected to:**
  - ArenaManager._on_got_hit() calls HitVfx.spawn(combat_root, info)
  - Receives hit info: pos, element, dmg, mult, dir, heavy, ko, hitstop, kb

#### 16. DamageNumber (`damage_number.gd`) - **Phase 4**
**Floating damage number popups**
- **What it does:**
  - Extends Label, shows damage value with optional "!" for super-effective
  - Static `spawn(parent: Node, info: Dictionary)` factory
  - Color coding: gold for super-effective (mult > 1.0), muted grey for resisted (mult < 1.0), red for KO, white for normal
  - KO hits use larger font (34), heavy hits use 28, normal use 20
  - Tween animation: rises 44-58px over 0.65s, pops scale (back ease), fades after 0.35s, auto-frees
  - KO adds slight random rotation
- **Connected to:**
  - ArenaManager._on_got_hit() calls DamageNumber.spawn(combat_root, info)

#### 17. Sfx (`sfx.gd`) - **Phase 4**
**Positional sound effect pool player**
- **What it does:**
  - Manages pool of 12 AudioStreamPlayer2D instances
  - Loads streams from `res://assets/audio/<name>.wav` on demand (caches)
  - Missing files silently skipped (drop in real audio to replace)
  - `play(sound, pos, volume_db, pitch)` - finds free player, sets position/volume/pitch, plays
  - Max distance 4000 (heard across arena)
- **Connected to:**
  - ArenaManager (created in _build_juice)
  - ArenaManager._on_got_hit() plays hit_light/hit_heavy/hit_ko + hit_super (super-effective)
  - ArenaManager._on_fighter_event() plays EVENT_SOUNDS mapping (jump, dash, attack, special1, special2, ultimate, shot, trap_set)
  - Element pitch variation via ELEMENT_PITCH constant

#### 18. Keybinds (`keybinds.gd`) - **new**
**The single place every key is defined** (`extends RefCounted`, no `class_name`; other scripts `preload("res://keybinds.gd")`)
- **What it does:**
  - `BINDINGS` const: action name -> physical keycode for P1/P2 gameplay (`pN_left/right/jump/attack/dash/special1/special2/ultimate/down/support/support_2/support_3`), P1/P2 character-select navigation (`pN_nav_up/down/left/right`, `pN_select`) and match actions (`menu_toggle` = Tab, `restart_round` = F5, `debug_hitboxes` = F1; P1: attack F, special 1 G, special 2 H, ultimate T, Down S; P2: arrows move/jump/Down, attack Num 4, dash Num 0, special 1 Num 5, special 2 Num 6, ultimate Num 8, support 3 Num -)
  - `EXTRA` const: LIST of extra keys per action (P2 menu nav also works on the arrow keys + Space). Extra Down keys: P1 Ctrl and Shift, P2 Num 2 and Num Enter - for keyboards that cannot send W + S + attack together (ghosting)
  - `debug_keytest` = F2 (toggles the key test overlay, `input_debug.gd`)
  - `register()` (static): adds every missing action to the `InputMap` (skips actions that already exist, e.g. ones defined in `project.godot`)
  - `rebind(action, keycode)` (static): replaces an action's key at runtime
  - `key_name(action)` (static): readable name of the key currently bound ("R", "Tab", "Num 4")
  - `fmt(text)` (static): replaces every `{action_name}` placeholder with that action's current key
- **Connected to:** `InputHandler.register_actions()` (calls `register()`), `GameText` (uses `fmt`), HUD controls hint and CharacterSelect mode hint (through GameText)

#### 19. GameText (`game_text.gd`) - **new**
**Player-facing strings, filled from live key bindings** (`extends RefCounted`, preloaded where used)
- **What it does:** holds `HELP_P1`, `HELP_P2`, `HELP_FOOTER`, `WIN_BANNER`, `MODE_PVP`, `MODE_PVCPU`, `MODE_CPUVCPU` and builds them with `Keybinds.fmt()` so a hint can never disagree with the real key
  - `mode_hint(mode)` -> text for the character-select mode label
  - `controls_help()` -> the 3-part controls hint shown by the HUD
  - `win_banner(winner_name)` -> "<NAME> WINS! (<restart key> to restart)"
- **Connected to:** `HUD.refresh_help()`, `CharacterSelect._update_mode_ui()`, `ArenaManager._on_died()`

#### 19a. KeyTest (`input_debug.gd`) - **new**
**F2 key-test overlay** (`extends CanvasLayer`, layer 100, `PROCESS_MODE_ALWAYS`, hidden at start)
- **What it does:** shows, for P1 and P2, which game actions the engine currently reports as pressed (with their key names), and a log of the last 10 raw key press/release events. It only reads input; it never changes gameplay. It exists to tell a keyboard problem (ghosting: the key never reaches the game) from a code problem.
- **Created by:** `ArenaManager._setup()` (`key_test = load("res://input_debug.gd").new()`); **toggled by:** `ArenaManager._unhandled_input()` on action `debug_keytest` (F2), but only while the select menu is hidden
- **Connected to:** `Keybinds.key_name()` (labels), `InputMap` actions `pN_left/right/jump/down/attack/dash/special1/special2/ultimate`

#### 20. Settings (`settings.gd`) - **autoload `Settings`**
**Persistent settings singleton** (`extends Node`, no `class_name` on purpose - it would hide the autoload)
- **What it does:**
  - Stores a `ConfigFile` at `user://settings.cfg` (`SETTINGS_PATH`), loaded in `_ready()` (`load_settings()`), saved on every `set_value()` (`save_settings()`)
  - `_defaults()` writes section `game`: `difficulty`="medium", `master_volume`=0.8, `sfx_volume`=1.0, `music_volume`=0.7, `last_p1_fighter`="marshadow", `last_p2_fighter`="gholdengo", `last_mode`="pvp"
  - `get_value("section/key", default)` / `set_value("section/key", value)` (renamed from `get`/`set` so they don't override Object methods)
  - Convenience pairs: `get/set_difficulty`, `get/set_master_volume`, `get/set_sfx_volume`, `get/set_music_volume`, `get/set_last_p1_fighter`, `get/set_last_p2_fighter`, `get/set_last_mode`
  - `last_mode` values: `pvp`, `pvcpu` (P2 CPU), `cpuvp` (P1 CPU), `cpuvcpu` (see CharacterSelect `mode_name()`)
  - Runtime flag (not saved): `view_mode_only` with `set_view_mode_only()`, `get_view_mode_only()`, `clear_view_mode_only()` - tells the arena to open fighter select instead of auto-starting a match
- **Connected to:** MainMenu, ModeSelect, OptionsMenu, CharacterSelect (`_on_start` saves the picks), ArenaManager (`_setup`, `_start_match` read mode/difficulty)

#### 21. UIManager (`ui_manager.gd`) - **autoload `UIManager`**
**Menu stack manager** (`extends Node`, no `class_name`)
- **What it does:**
  - `signal menu_changed(menu_name)`; `var current_menu: CanvasLayer`; `var menu_stack: Array[String]`
  - `show_menu(scene_path)`: frees the current menu, instantiates the new scene on the root and pushes the path
  - `go_back()`: pops to the previous menu; with one entry left it clears the stack and frees the menu (revealing the scene underneath, e.g. the main menu)
  - `clear_stack()`: frees the current menu and empties the stack; `get_current_menu()` -> top path or ""
- **Connected to:** MainMenu (Play, Options), ModeSelect (Back, Continue), OptionsMenu (Back)

#### 22. Menu scenes (`main_menu.gd`, `mode_select.gd`, `options_menu.gd` + `.tscn`) - **new**
**Three `CanvasLayer` screens driven by %unique-name nodes** (`main_scene` is `main_menu.tscn`)
- **MainMenu:** Play -> `Settings.set_view_mode_only(true)` then `change_scene_to_file("res://main.tscn")` (the select screen opens there; the mode is chosen on it); Characters -> `Settings.set_view_mode_only(true)` then `change_scene_to_file("res://main.tscn")`; Options -> `UIManager.show_menu("res://options_menu.tscn")`; Quit -> `get_tree().quit()`
- **ModeSelect:** `signal mode_selected(mode, difficulty)`; PvP / PvCPU / CPUvCPU buttons set `selected_mode` ("pvp" | "pvcpu" | "cpuvcpu"); difficulty slider (0-2 -> "easy" | "medium" | "hard") is only shown for CPU modes; CONTINUE (`_on_mode_confirmed`) saves `last_mode` + `difficulty`, sets `view_mode_only`, emits the signal, calls `UIManager.clear_stack()` and changes to `main.tscn`; Back -> `UIManager.go_back()`
- **OptionsMenu:** difficulty, master, SFX and music sliders write straight to `Settings`; Back -> `UIManager.go_back()`
- **Connected to:** `Settings`, `UIManager`, `main.tscn` (ArenaManager takes over from there)

#### 23. CharacterSelect (`character_select.gd` + `.tscn`) - **redesigned 2026-10-14, flow changed the same day**
**Smash-style fighter select, instanced hidden by ArenaManager.** The `.tscn` holds only the root `CanvasLayer` (script), `BackgroundShade` (ColorRect) and `BackgroundArt` (TextureRect, `assets/background.png`). Everything else is built in code by `_build_ui()` under a full-rect `_root` Control. Layout on the 1920x1080 viewport: top bar (BACK, title, mode label "PLAYER VS CPU" etc., `CPU LEVEL` button), a centred grid of fighter tiles in rows of `ROW_LENGTH` (5) inside a `ScrollContainer` of `GRID_HEIGHT` (380 px), two side panels of fixed `CARD_HEIGHT` (400 px) (P1 left, P2 right), bottom bar (controls hint, START).
- **Modular:** a fighter added to `ArenaManager.ROSTER` gets a tile automatically; rows wrap by `ROW_LENGTH`; the grid scrolls past `GRID_HEIGHT`; stat bars and move lists come from each fighter's own script. Tile, grid and panel sizes are constants, so sprite size never changes a tile or button height.
- **Mode is chosen on this screen:** each side has a `PLAYER` / `CPU` switch (button, or keys `p1_cpu_toggle` = Q and `p2_cpu_toggle` = Num +). The two switches give the mode through `mode_name(p1_cpu, p2_cpu)` -> `pvp` / `pvcpu` (P2 CPU) / `cpuvp` (P1 CPU) / `cpuvcpu`. `mode_is_cpu(mode, side)` is the inverse. The old mode screen is no longer in the flow (`mode_select.tscn` is unused).
- **What it does:**
  - Signals: `start_requested(p1_id, p2_id)`, `cancel_requested`, `mode_changed(is_pvp)` (emitted when a side's switch changes)
  - Vars: `p1_cpu` (default false), `p2_cpu` (default true), `p1_index`/`p2_index`, `p1_ready`/`p2_ready`, `difficulty`, and `returns_to_menu` (true when opened from the main menu)
  - `open_select(fighters, p1_idx, p2_idx, p_mode, p_difficulty, from_menu)` stores the roster, sets the switches from `p_mode`, clamps the indices, resets the ready flags, builds the UI (once), builds the grid (rebuilt only when the roster ids change), refreshes everything and shows the screen. `_load_roster_from_arena()` falls back to `ArenaManager.ROSTER` through `get_script_constant_map()`.
  - Tiles: `_build_grid()` makes one row `HBoxContainer` per `ROW_LENGTH` entries (centred); `_add_tile(i, row)` makes a fixed `TILE_SIZE` (180x176) tile with an `AnimatedPortrait` at 2x (`TILE_PORTRAIT` 128 px), a name bar and two corner badges (`P1`/`CPU n`) that show only while a cursor sits on that tile (`_badge()`). A tile under both cursors gets a gold border (`_refresh_tiles()`). Left click on a tile moves P1's cursor there, right click moves P2's (`_on_tile_input()`).
  - Side panels: `_make_card(n)` builds the header (PLAYER/CPU switch, title, READY! stamp, READY button), a 192 px `AnimatedPortrait` with the name, element chips, STATS (three `ProgressBar`s: HP, SPEED, JUMP, drawn relative to the roster by `_stat_fill()`), and MOVES (3 columns: title, damage with `xN` for multi-hit, stamina / cooldown or "needs full gauge" from `_move_detail()`).
  - `_refresh_card(n)` re-fills a panel for the cursor's fighter. The portrait swaps and pops (`_punch()`) only when the fighter changes. The switch text and READY button follow `_is_cpu_side(n)`.
  - `_refresh_all()` -> mode label (`_mode_text()`), CPU LEVEL button, `_refresh_tiles()`, `_refresh_card(1)` / `(2)`, `_refresh_start_button()`, and the controls hint (two lines: keys, then the Down-move tip).
  - `_is_ready(n)`: a CPU side is always ready; a player side is ready after its READY press. `_can_start()` = both sides ready (so PvP needs both, PvCPU the player only, CPU vs CPU nothing).
  - `_toggle_side(n)` flips a side's CPU flag and resets that side's READY. `_cycle_level()` cycles easy -> medium -> hard and saves it with `Settings.set_difficulty()`.
  - Cursors: `_step(index, dx, dy)` moves one tile (wraps across the row order) or one row (`dy`, clamped to the last tile of a short row). `_move_cursor(n, dx, dy)` and `_place_cursor(n, i)` clear that side's READY and scroll the tile into view (`_scroll_to()`).
  - `_input()` (only while visible): Tab (`menu_toggle`) = BACK, `cpu_level` (C) cycles the level, `p1_cpu_toggle` / `p2_cpu_toggle`, `p1_select` / `p2_select` (`_select_pressed()`: the first press readies the side, the next starts the match once `_can_start()`), then `p1_nav_*` and `p2_nav_*` (P2 arrows and numpad both work).
  - `_on_start()` prefixes CPU sides with `cpu_`, saves `last_p1/p2_fighter`, `last_mode` (`mode_name()`) and `difficulty` into Settings, emits `start_requested`, hides and unpauses. `_on_back()` emits `cancel_requested`, hides and unpauses; ArenaManager decides where BACK leads (see `_on_selection_cancelled`).
  - `_data_instance(data)` instantiates the roster scene (not added to the tree) and calls `_apply_archetype()` by hand so hp, speed, jump and types are real values. `_fighter_info(data)` reads types, stats and the four moves once and caches them by id; `_hit_count(m)` gives the number of hits of a multi-hit move or projectile volley.
  - Helpers: `_label()`, `_button()` (focus off, so Enter only means "ready"), `_spacer()`, `_box()` (StyleBoxFlat), `_pad()`, `_readable()`, `_side_color()`, `_side_title()` / `_side_tag()`, `_clear()`, `_punch()`.
- **Connected to:** ArenaManager (signals; `open_select` from the main menu's Play/Characters through `_setup()`, and from Tab in a match; `CharacterSelect.mode_name()` / `mode_is_cpu()` for the match mode), ROSTER, AnimatedPortrait (one per tile and per panel), Fighter scenes (stats and moves, read through `_data_instance`), StatsComponent.Element and HitVfx.STYLE (element chips), Keybinds (controls hint, Down-move hint), InputHandler (`register_actions()`), Settings (last fighters, mode, difficulty)

#### 27. Behavior-tree nodes (`AIBehavior.gd`, `bt_*.gd`) - **new**
**AI building blocks; all extend `AIBehavior` (a `RefCounted`, so children are plain `var`s, never `@export`)**
- **AIBehavior:** `tick(ai: AIController) -> Status` (SUCCESS / FAILURE / RUNNING), `_reset()`, `_get_delta(ai)`
- **Selector** (`bt_selector.gd`): `children: Array[AIBehavior]`; first child that returns SUCCESS or RUNNING wins
- **Sequence** (`bt_sequence.gd`): `children`, `_current_index`; FAILURE if any child fails, SUCCESS when all succeed
- **Condition** (`bt_condition.gd`): `check_func: Callable` returning bool
- **Action** (`bt_action.gd`): `action_name` (attack, special1, special2, ultimate, dash, jump), `duration` (0 = instant SUCCESS); buffers the input on the fighter through the AIController
- **Cooldown** (`bt_cooldown.gd`): `child`, `cooldown_time`; child only runs when ready
- **Inverter** (`bt_inverter.gd`): `child`; flips SUCCESS/FAILURE
- **Repeater** (`bt_repeater.gd`): `child`, `count` (-1 = infinite); returns RUNNING while repeating, SUCCESS once the child has succeeded `count` times, FAILURE if the child fails
- **UntilFail** (`bt_until_fail.gd`): `child`; returns RUNNING while the child keeps succeeding/running and SUCCESS the moment it fails
- **Connected to:** AIController (`_build_behavior_tree()` and the `_build_*_tree()` helpers create them in code; the `.tres` profiles hold no tree data)

- **Connected to:** Fighter exit_*_state hooks call this

#### 26. Fighter aerial attack (`_enter_move` / `_run_move` / `_aerial_motion`) - **reworked**
- **What it does:** a basic attack started while airborne becomes a diagonal dive. It has its OWN timing, independent of the ground move: the hitbox turns on at frame `AERIAL_ON` (2) and stays on while diving (up to `AERIAL_ACTIVE` frames); horizontal speed `AERIAL_ATTACK_PUSH`, minimum downward speed `AERIAL_HOP`, downward knockback `AERIAL_KB_Y`, hitbox lengthened 1.15x and rotated to `AERIAL_ANGLE`; the sprite rotates along the dive.
- **Landing no longer deletes the attack:** `_aerial_motion()` records `aerial_land` (the move frame the fighter touched the floor), keeps the hitbox on for at least `AERIAL_MIN_ACTIVE` frames from its start, slides to a stop, then plays `AERIAL_LAND_LAG` frames of recovery before `_finish_move()`. (Old bug: landing after frame 2 ended the move, so any fighter whose ground basic starts late - Tinkaton `on` = 10, Gholdengo 6, Scizor 4 - touched the floor before the hitbox ever existed and the aerial did nothing.)
- **Down + attack in the air = spike dive:** `_enter_move()` captures whether Down was wanted (`want_down`) before it clears `down_next`; an airborne basic with Down uses `AERIAL_DOWN_*`: steeper (~69 deg), faster, 1.15x damage, half the horizontal knockback, downward knockback `AERIAL_DOWN_KB_Y` (a spike), min active `AERIAL_DOWN_MIN_ACTIVE`, landing lag `AERIAL_DOWN_LAND_LAG`. `receive_hit()` turns the spike into an upward pop (`AERIAL_DOWN_POP_Y`) if the target is on the ground. The fighter's own `basic_down` is the GROUND move only.
- **Connected to:** `_enter_move()` sets it up and marks the move copy (`is_aerial`, `aerial_down`, `aerial_ang`, `aerial_push`, `aerial_hop`); `_run_move()` delegates the melee motion to `_aerial_motion()` (returns true when the move finished); `_update_visuals()` rotates the sprite until landing; `receive_hit()` reads `is_aerial` / `aerial_down`

#### 27. Fighter.state_hitstun(delta) and Fighter._tech() - **new**
- **What they do:** hitstun applies gravity, DI (`DI_INFLUENCE`) and friction; a tech is only possible after being launched (`stun_air`) and landing: a FRESH dash press (`fresh("dash", TECH_PRESS_FRAMES)`) within `TECH_WINDOW` frames of touchdown while `tech_cd` is 0 and stamina >= `TECH_COST` calls `_tech()`, which consumes the press, spends `TECH_COST`, grants `TECH_IFRAMES` invincibility, roots the fighter for `TECH_RECOVERY`, starts `TECH_COOLDOWN`, zeroes velocity and emits event "tech"
- **Connected to:** `receive_hit()` sets `stun_air` and `tech_since_land`; the input buffer's "dash" slot

#### 28. Fighter.enter_dash() / state_dash() / exit_dash() - **new**
- **What they do:** `enter_dash()` spends `dash_cost`, picks `dash_dir` from input (or facing), goes invincible and sets `air_dashed` when airborne; `state_dash()` moves at `dash_speed` with an ease-out after `DASH_EASE_START`, drops invincibility after `iframe_frames`, and ends after `dash_frames` keeping `DASH_CARRY` of the speed; `exit_dash()` restores the hurtbox
- **Connected to:** `_try_actions()` (starts it), `_wavedash()` (the air variant stays in the jump state)

#### 29. Fighter._move_dive(m, f, delta) - **new**
- **What it does:** runs `kind == "dive"` moves (Blaziken's dive kick): hop, then slam diagonally down at `dive_speed` / `dive_dx` from frame `dive_start` until landing; uses `dive_active` / `dive_end`
- **Connected to:** `_run_move()` delegates dive moves here

#### 30. Smaller Fighter helpers - **new**
- `get_types() -> Array` (types, [0] is the attack type), `_define_moves_default()` (fallback move set), `cooldown_ratio(key) -> float` (0-1 for the skill slots), `_restore_hurtbox()` (clears invincibility), `_hitbox_off()`, `variant(base, over) -> Dictionary` (copy of `base` with `over` merged on top; used to write a fighter's `<key>_down` as "the normal move, except ..."), `_derive_down_variant(key, base)` (builds the GENERIC Down variant for any move a fighter does not define itself: melee = lower/wider sweep that pops up, projectile = low fast shot, trap = placed close, dive = steeper), `_move_data(key, down)` (returns `moves[key + "_down"]` or `moves[key]`), `_gravity(delta, cap_mult := 1.0)` (gravity step; `cap_mult` scales the `max_fall` cap, used by the fast fall), `_move_animation_profile(key)` (per-slot anim rate/tilt/scale/tint: basic 1.28 / special1 0.96 / special2 0.82 / ultimate 0.66 rates), `_fx_tex(path)` (cached texture loader for move FX), `state_special1/2`, `state_ultimate` and their `enter_*` / `exit_*` hooks (all delegate to `_enter_move` / `_run_move` / `_end_move`)

### AIController Functions (`AIController.gd`) - **rewritten 2026-10-14 (AI pass)**

#### 1. AIController.setup(fighter) / set_target(target)
- **What they do:** `setup()` grabs the fighter's InputHandler (put into `remote = true`), runs `_load_profile()`, `_apply_difficulty()` and `_build_behavior_tree()`; `set_target()` sets `opponent_fighter`
- **Connected to:** `ArenaManager._attach_ai()`

#### 2. AIController._physics_process(delta)
- **What it does, every physics frame:** `_update_whiff_tracking()` (did the opponent's melee move connect, and if not, open a punish window), `_update_own_hits()` (our move connected: queue the combo follow-up now, not at the next decision), `_drive_movement()` (apply `move_dir`, hold jump, `input_handler.decay_buffers()`, face the opponent).
- **At the reaction interval** (`reaction_time`): sets `decision_dt` (real seconds since the last decision), then `_update_movement()` and `behavior_tree.tick(self)`.
- **Connected to:** Godot engine; fair information only (positions, velocity, the opponent's state, current move and `landed_hit`, projectiles on screen); never the opponent's input buffer

#### 3. Tree builders and checks
- `_build_behavior_tree()`: root Selector with priorities 1) anti-air (ungated, only when `anti_air_move` is set), 2) whiff punish (`punish_move`), 3) zoning response, 4) the engagement tree from `_build_engagement_tree()` (`_build_aggressive_tree()`, `_build_defensive_tree()`, `_build_zoning_tree()`, `_build_hit_and_run_tree()`, `_build_tricky_tree()` or `_build_balanced_tree()` by `profile.personality`; unknown values use balanced). The combo branch was removed: follow-ups are queued from `_update_own_hits()` instead.
- **Attack gating:** `_act(name, duration, gated)` wraps attack-type actions (`attack`, `basic`, `special1`, `special2`, `ultimate`) in `Sequence[Condition(_can_use), Action]`. `_can_use(action)`: projectile moves need the opponent between `PROJECTILE_MIN` (90) and `PROJECTILE_MAX` (600); traps need `TRAP_MAX` (420); melee / dive needs `dx <= _melee_reach(key)` and `dy <= 50`. Plain attacks also roll against `aggressiveness`.
- **Reach:** `_melee_reach(key)` = `|off.x| + size.x / 2 + BODY_RADIUS` (14), read from the move's own numbers (basic = 70 px).
- **Range:** `_in_range(range_type)`: close = within basic reach; mid = beyond it and under `FAR_RANGE` (300); far = 300 or more. `_has_opponent()` guards every check.
- **Conditions:** `_always_true()`, `_in_range(range_type)`, `_can_use(action)`, `_check_anti_air()` (opponent rising, within 100 px, we are on the floor), `_check_whiff_punish()` (`_whiff_frames > 0`), `_check_zoning_response()` (a `Projectile` whose `shooter` is the opponent, closer than `ZONING_SIGHT` (360) and heading our way, or the opponent casting a projectile move now); helper `_get_zoning_action()`.
- **Movement:** `_update_movement()` (run at each decision). Close fighters walk until within basic reach minus 10 px; mid / far fighters keep `170` / `FAR_RANGE` px with a band of `16 + (1 - accuracy) * 30` px. `_drive_movement()` applies it every frame.
- **Input out:** `buffer_action(action)` writes `input_handler.buffer[action]` (window from `InputHandler.BUFFER_WINDOWS`) and, for attacks / specials, `down_at[action] = _pick_down(action)` (situational Down variant, scaled by `accuracy`). Jump holds for 18 frames.
- **Own hits:** `_update_own_hits()` reads `target_fighter.landed_hit` and `cur_key`; once per move, each `combo_chains` entry whose `trigger` matches queues its `followup` with probability `accuracy`.
- **Whiff tracking:** `_update_whiff_tracking()` watches the opponent's `sm.current` and `cur_move.kind`. When a melee move ends without `landed_hit`, `_whiff_frames = WHIFF_WINDOW` (36 frames).
- **Connected to:** AIProfile, the bt_* nodes (their `_get_delta` returns `decision_dt`), the fighter's InputHandler (`decay_buffers()`, `buffer`, `down_at`), Fighter (`landed_hit`, `cur_key`, `cur_move`, `sm`), Projectile (`shooter`, `dir`)

## Known Issues / Code Notes (as of 2026-10-14) - **new**
Verified by reading the code; these are observations, not fixes.
1. ~~**Shared move dictionary is mutated by aerial attacks.**~~ **Fixed** (`cur_move = ....duplicate()`). Original note: `_enter_move()` sets `cur_move = moves[key]` (a reference) and then writes `cur_move.kb` and `cur_move.is_aerial` for an airborne basic attack. After the first aerial, that fighter's grounded basic attack keeps the aerial downward knockback (`kb.y` = 100). Fix idea: `cur_move = moves[key].duplicate()` (or store the aerial values in separate variables).
2. ~~**`Y` is bound twice.**~~ **Fixed** (`restart_round` is now F5). Original note: `keybinds.gd` binds both `p1_support_3` and `restart_round` to `KEY_Y`, so pressing Y restarts the round and also triggers P1's third support call.
3. **`ScreenShake` (`screen_shake.gd`) is unused** - `ArenaCamera` does the shake. The file can be deleted or kept as reference.
4. **Brawler and Zoner are not in `ROSTER`** and have no AI profile (they use the default balanced profile); `AIController._load_profile()` looks the profile up by scene file name; its class-name mapping (Brawler -> scizor, Zoner -> gholdengo) only applies when a fighter has no `scene_file_path`.
5. **`ModeSelect.mode_selected` and `UIManager.menu_changed` have no listeners** - state travels through `Settings` instead.
6. **Arena geometry is a flat box** (floor, ceiling, two walls); a muzzle point inside a wall used to delete projectiles (a fighter standing against a wall facing it) - keep that in mind when adding platforms or changing `proj_off`.
7. ~~**Aerial basic attacks were cancelled by landing before their hitbox existed**~~ **Fixed** (own timing from `AERIAL_ON`, hitbox kept on for `AERIAL_MIN_ACTIVE` frames, landing lag instead of a cancel). Reported for Tinkaton and other late-hitbox fighters.
8. ~~**Fast fall only fell faster; it never shortened a jump, and was disabled while holding left/right**~~ **Fixed** (see 14a).
9. ~~**Attack seemed to do nothing while W and S were held.**~~ **Mitigated 2026-10-11.** Reading the code found no software block: `p1_jump` (W), `p1_down` (S) and `p1_attack` (Q at the time; now F) are separate actions and nothing consumes them. The usual cause is keyboard ghosting (many keyboards cannot report W + S + attack together; the key never reaches the game). Mitigations: Down TAP latch (no need to hold S together with W and Q), alternate Down keys on other parts of the keyboard (Ctrl / Shift, Num 2 / Num Enter), event-based press capture, and the F2 key test to see what the keyboard really sends.
10. **Down variants do not exist for the ultimate**, and Brawler / Zoner (not in `ROSTER`) still use the generic `_derive_down_variant()` moves.
11. **No `ultimate` sound file.** `ArenaManager.EVENT_SOUNDS` maps the ultimate event to `"ultimate"`, but `assets/audio/` has no `ultimate.wav`, so `Sfx.play()` skips it silently (the other 10 files exist).
12. **Misplaced comment in `input_handler.gd`.** The comment above `const COMBAT_ACTIONS` says "Set by the Fighter during a dash ...", but that describes `hold_buffers` (set in `Fighter._physics_process()`). Comment only; no behaviour change.

## Down move guide - **reworked 2026-10-11**
**How to use it:** hold Down (P1 `S` - alternates `Ctrl` / `Shift`; P2 `Arrow Down` - alternates `Num 2` / `Num Enter`) and press attack / special 1 / special 2, or TAP Down a few frames before or after the button (it still counts for 8 frames). Cooldowns, stamina cost, cancel chains, hit sounds and the animation slot are shared with the normal move.
- **On the ground:** `basic_down` / `special1_down` / `special2_down` of the fighter (below).
- **In the air:** Down + attack is the spike dive (`AERIAL_DOWN_*`); Down + special uses the same `special*_down` data as on the ground; Down alone is fast fall / short hop.
- **Bots** pick Down variants situationally (`AIController._pick_down()`, which now judges the Down move's own kind/reach).
- **Rule used for the redesign:** every Down move changes WHAT the move does (a trip, a shockwave, a skipping projectile, a delayed geyser, a teleport, a rooting arrow...), not only where the hitbox sits.
